# Screen Blueprint Studio プロダクトロードマップ

[English](./ROADMAP.md)

最終更新: 2026年9月1日

Screen Blueprint Studioは、実装前や改修時にWeb画面の見た目と動きをすり合わせるためのツールです。プロダクトマネージャー、デザイナー、エンジニア、QA担当者が、画面構成、状態、共通UI、データに基づく一覧、ユーザー操作、APIの結果をひとつの視覚的な画面仕様にまとめ、ワイヤーフレームと文章による仕様のずれを減らせます。

## このリリースで利用可能

- **複数画面と状態を視覚的に設計する。** 複数の画面を作成してつなぎ、通常、読み込み中、データなし、保存中、成功、エラーなどの状態ごとに見た目を示せます。状態ごとに別のワイヤーフレームを管理しなくても、確認したい場面が目で分かります。

- **共通UIとバリエーションを一か所で管理する。** 繰り返し使う画面部分をShared Componentとして定義し、利用者が変更できる項目と、承認済みの見た目のバリエーションを用意できます。共通ヘッダーやフォーム部分を各画面で個別に直さず、一度の更新で揃えられます。

- **Collectionで一覧をデータに基づいて表現する。** 行やカードを一度定義し、各項目を手作業で複製せず、データの件数に応じて繰り返す形で示せます。一覧画面の仕様を簡潔に保ち、現在の項目からどの値を表示するかを明確にできます。

- **ユーザー操作とAPIの動作を記録する。** 操作部品にイベントを設定し、実行する処理の順序、フォーム項目とAPIリクエストの対応、成功時と失敗時の画面状態を記録できます。保存ボタンを押したときに何が起きるべきかを、デザイナー、エンジニア、QAが同じ画面仕様で確認できます。

- **完成画面に近い構造を仕様として表現する。** 画像と安全なリンクを追加し、縦、横、グリッドのレイアウトを選び、重ねて表示する要素や画面枠に固定する要素を制約付きで配置できます。ピクセル単位の自由描画に頼らず、実際の構造や移動先が伝わる画面仕様を作れます。

- **WebMCPを通じたAI変更を人が確認する。** AIエージェントは現在の画面と選択箇所を読み取り、アプリ内に確認可能な変更案を作成できます。保存済みのプロジェクトが変わる前に、人が結果をプレビューして反映または破棄します。

## 今後の追加予定

### 共有とバージョン管理に使えるプロジェクトファイル

現在のプロジェクトはブラウザ内に保存されるため、別の環境へ移す、別プロジェクトで再利用する、コード変更と一緒に確認するといった作業が難しくなっています。

JSONとYAMLの読み込み・書き出しを追加し、プロジェクト全体をファイルとして扱えるようにします。読み込むファイルを検証し、編集を続けるために必要な情報を保ちます。

たとえば、購入手続き画面一式を書き出してGitへ登録し、変更箇所を差分で確認できます。別のPCで読み込んだり、関連製品を設計するときのひな形として再利用したりすることもできます。

### どのような画面部品や動作も仕様に残す

現在のエディタは、あらかじめ対応している画面部品、きっかけとなる操作、実行内容、API結果を選択肢として案内します。しかし、製品固有の部品や利用頻度の低い動作が選択肢にない場合でも、専用欄がないという理由で大切な仕様が失われてはいけません。

よく使うケースには、引き続き構造化された選択肢、参照先の確認、入力内容の検証、WebMCPによる操作支援を提供します。組み込み形式がない画面部品、動作のきっかけ、実行内容、条件、データの参照元についても、名前、説明、条件、入力、期待する結果、例、実装上の注意を記録できるようにします。保存、再表示、読み込み、書き出しを行ってもその情報を失わず、未知の種類という理由で拒否せずに表示します。これは意図する動作を記述するための機能であり、任意のHTMLやJavaScriptを実行するものではありません。

具体例として、画面を開いたときのデータ読み込み、Selectの変更に応じた再検索、一覧で選んだ行のIDをAPIへ渡す処理、URLパラメーターを表示内容に使う処理、前の画面へ戻る、外部ページを開く、ファイルをダウンロードする、指定箇所へスクロールする、403と404で異なる状態を表示する、といった仕様を扱えます。これらは入力を助ける例であり、記録できる内容を限定する一覧ではありません。

### 編集せずに画面操作を確認する

現在のキャンバスは編集を中心に作られているため、複数の手順にまたがる操作を確認するときは、仕様を変更しないよう注意しながら、個別の状態と動作設定を読み合わせる必要があります。

編集操作を無効にした専用の確認モードを追加し、仮のデータを使って画面、重ねて表示する要素、処理、API結果の流れをたどれるようにします。実際のバックエンドへ接続したり、任意のJavaScriptを実行したりする機能ではありません。

たとえば、削除ボタンを押し、確認モーダルの内容を見て、APIが成功した場合と失敗した場合の両方を続けて確認できます。プロダクト、開発、QAの担当者が、画面仕様を変更せずに同じ操作について話し合えます。
